What this file can explain

  • Where failures cluster: origin site, lane, receiver state, postcode, remoteness.
  • When: week, ETA weekday, volume surges.
  • What kind: service promise (1-day vs 5-day), carton vs pallet, size of the miss in business days.
  • Cost drivers: charged vs dead kg, distance mix, cost per lane.

What it can't, yet

  • No carrier reason codes or scan events, so a true cause (missed linehaul, futile delivery, receiver closed) has to come from the carrier's tracking or exception feed.
  • ETA is the carrier's own date, not your contracted SLA. Contract transit times should be the yardstick.
  • In-full is item count only. Damage and SKU shortages sit in claims and returns data.
  • Public holidays aren't removed yet, so a few holiday weeks overstate lateness.

Architecture

Same pattern as the delivery-exception agent: deterministic code owns every number and every routing decision; LLM agents only segment, explain and draft, and a critic checks each claim against the metrics engine before anything reaches a person.

flowchart LR
  A[Carrier connote exports, scan events, POD] --> P[Ingest and preprocessor - deterministic]
  P --> M[(Metrics engine - DIFOT, cost, km - deterministic)]
  M --> O{Orchestrator - deterministic router}
  O --> S[Failure segmentation agent]
  S --> R[RCA agent - RAG over SLA, rate card, ops notes]
  R --> C[Critic - every claim cites a metric]
  C -->|revise, max 2| R
  C -->|approved| W[Reporting and carrier-claim agent]
  O --> V[Viz query agent - plain English to map view]
  V --> UI[Map, time-lapse and trend views]
  M --> UI
  W --> H([Human approves pack or claim])

Build phases

  • 1. Metrics and visuals. Preprocessor, metrics engine and these views. No LLM. Reconcile DIFOT against your current report.
  • 2. Segmentation and critic. Ranked failure clusters with plain-English summaries and figures checked by the critic.
  • 3. RCA with scan events. Connect the carrier tracking/exception feed; label 100 failures by hand as ground truth.
  • 4. Ask the map and carrier packs. Natural-language views, weekly carrier pack, draft claims.

Evaluation

  • Metric reconciliation: engine vs a hand-built Excel pivot, exact match.
  • RCA accuracy vs 100 hand-labelled failures, by cause category.
  • Claim grounding rate: share of critic-approved statements traceable to a metric call.
  • Portfolio version: anonymised sites, scaled costs, shifted dates, so the demo can be public.
