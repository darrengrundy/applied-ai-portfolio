# Applied AI Portfolio

Practical AI engineering projects, working demonstrations, and case studies developed through formal study and independent work at [My Lane](https://mylaneai.com.au/).

The portfolio focuses on applied solutions using Microsoft Foundry, Azure, Python, generative AI, multi-agent systems, data analytics, and transport and supply-chain domain knowledge.

> This portfolio is being developed progressively. Project pages will be published after their code, documentation, attribution, and security have been reviewed.

## Portfolio areas

### Learning projects

Hands-on assignments and demonstrations completed through structured AI engineering programs. These projects show the development of core capabilities such as model deployment, conversational applications, tool use, retrieval, agents, observability, and responsible AI.

- [DAX AI Engineering Bootcamp](learning-projects/ai-engineering-bootcamp/) - Weeks 1-8 coursework validated in VS Code; 70 Python files preserved, with the Azure assignment tracker maintained separately
- [QUT Data Analytics Capstone (IFQ721)](learning-projects/qut-data-analytics-capstone/) - multi-agent analytics framework over IoT telemetry
- [Microsoft AI Engineering (AI-103)](learning-projects/microsoft-ai-engineering/) - 30-exercise tracker with shared DAX evidence mapped
- Quantic AI Engineering - commencing late August 2026

### My Lane projects

Independent applied-AI concepts and prototypes focused on operational decision support, transport safety, supply-chain analytics, and regulatory compliance.

- [Multi-Agent Last-Mile Delivery Exception Handler](my-lane-projects/delivery-exception-agent/) - complete evaluated POC, published
- [Multi-Agent AI for Transport Chain of Responsibility Compliance](my-lane-projects/transport-cor-multi-agent/) - working prototype, published
- Distribution LEAN Waste Multi-Agent System - in development
- Additional projects will be added as their source code is recovered and prepared

### Earlier projects

Selected earlier experiments and coursework that remain useful as evidence of technical growth. Only original or appropriately attributed work will be included.

## Documentation standard

Each published project will include:

- the problem and intended users;
- solution architecture and key design decisions;
- technologies and services used;
- setup and demonstration instructions;
- screenshots or other evidence of a working result;
- lessons learned, limitations, and possible improvements;
- attribution for starter code, learning materials, and external sources; and
- a security review confirming that credentials and sensitive data are excluded.
